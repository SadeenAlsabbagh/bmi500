ERROR HANDLING ⚠️
------------------
Over-engineered and misplaced. Type/value checks are verbose and scattered,
and checking element types *inside* the loop is a major performance problem
at scale.

  BAD — O(n) type checks per row, per element. At 1000x1000 this runs 1M checks:

    for i in range(len(vector_a)):
        if not isinstance(vector_a[i], (int, float)) or ...:

RECOMMENDATION:
  Either validate upfront in a single pass before the loop, or drop runtime
  type-checking entirely and rely on Python's natural TypeError from bad
  arithmetic. If validation is required, use a helper:

    def _validate_numeric_list(v, name):
        if not isinstance(v, list) or not v:
            raise ValueError(f"{name} must be a non-empty list.")
        if not all(isinstance(x, (int, float)) for x in v):
            raise TypeError(f"{name} elements must be numeric.")

CODE DESIGN ⚠️
---------------
- dot_product() shouldn't own input validation beyond what's needed for the
  math — length equality is correct, but type-checking individual elements
  belongs at the boundary.
- matrix_vector_product() delegates well to dot_product(), which is good.
  But it re-validates vector emptiness after dot_product() would catch it anyway.
- No support for numpy arrays or iterables beyond list — overly restrictive
  for a math utility.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

READABILITY ✅ / ⚠️
--------------------
Generally clean, but:

  UNNECESSARY — range + index is less Pythonic than zip:

    for i in range(len(vector_a)):
        result += vector_a[i] * vector_b[i]

RECOMMENDATION — Use zip instead:

    result = sum(a * b for a, b in zip(vector_a, vector_b))

  This is shorter, clearer, and eliminates the index variable entirely.

UNNECESSARY COMPLEXITY ⚠️
--------------------------
The manual loop in dot_product() reinvents sum(a*b for a,b in zip(...)) or
math.fsum (for precision). For a 1000×1000 benchmark, this is also ~100×
slower than numpy. If performance matters at all, note this clearly.

TEST COVERAGE 🔴
-----------------
main() is a smoke test, not a test suite. It only verifies the happy path
runs without crashing. Missing:
  - Unit tests for dot_product() (known inputs → expected output)
  - Error path tests (wrong lengths, wrong types)
  - Edge case tests (single-element vectors, negative values)

RECOMMENDATION — Use pytest or unittest:

    def test_dot_product_basic():
        assert dot_product([1, 2, 3], [4, 5, 6]) == 32

    def test_dot_product_length_mismatch():
        with pytest.raises(ValueError):
            dot_product([1, 2], [1])
